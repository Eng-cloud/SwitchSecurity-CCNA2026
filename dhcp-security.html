📡 DHCP Security

مين له حق يوزّع عناوين IP في الشبكة؟ ومين يقدر يدّعي إنه البوابة؟

01 المشكلة

العميل لمّا يشتغل يصرخ في الشبكة: "أبغى IP!" (DHCP Discover)، وأول سيرفر يرد ياخذ منه العميل كل شي: الـ IP، والبوابة (Gateway)، والـ DNS.

المشكلة: الـ Switch ما يفرّق بين سيرفر شرعي وسيرفر مزيّف. أي جهاز يقدر يدّعي إنه DHCP Server — وهنا يبدأ الخطر.

02 ليش اخترعتها Cisco؟

عشان تعطي الـ Switch القدرة يفرز رسائل DHCP: يسمح للسيرفر الشرعي فقط، ويبني سجل بمين أخذ أي IP ومن أي منفذ. هذا السجل (Binding Table) هو الأساس اللي يبني عليه DAI بعدين.

03 كيف كان الوضع قبلها؟

  • أي جهاز يوصل الشبكة ويشغّل DHCP Server مزيّف ← يوزّع بوابة خاطئة تمرّ الترافيك من عنده (MITM).
  • مهاجم يغرق السيرفر الشرعي بطلبات وهمية حتى يخلص مخزون العناوين (DHCP Starvation).
  • ما فيه أي سجل يربط الـ IP بالـ MAC بالمنفذ — فما فيه أساس نتحقق منه لاحقًا.

04 كيف تتم الهجمات؟

1) Rogue DHCP Server: جهاز المهاجم يرد على طلبات العملاء ويعطيهم بوابة = عنوانه هو. كل ترافيك الضحية يمرّ من المهاجم قبل ما يوصل الإنترنت ← تنصّت وتعديل.

2) DHCP Starvation: المهاجم يرسل آلاف الـ Discover بعناوين MAC مزيّفة حتى ينفد مخزون الـ DHCP الشرعي، فيضطر العملاء ياخذون من سيرفره المزيّف.

الحل: DHCP Snooping يمنع (1) بتصنيف المنافذ، والـ rate-limit (أو Port Security) يخفّف (2).

05 كيف يعمل DHCP Snooping؟ — جرّبه

الفكرة: نصنّف المنافذ إلى Trusted (توصل للسيرفر الشرعي أو للـ Switches الثانية) وUntrusted (توصل للأجهزة/المستخدمين). رسائل السيرفر (Offer/Ack) القادمة من منفذ Untrusted تُرمى — لأن المفروض ما فيه سيرفر خلف المستخدمين.

06 Dynamic ARP Inspection (DAI) — جرّبه

DAI يبني على جدول الـ Binding: يفحص كل رسالة ARP على المنافذ Untrusted، ويتأكد إن ربط IP ↔ MAC مطابق للسجل. لو مهاجم ادّعى إن IP البوابة = MAC حقّه (ARP Poisoning)، DAI يرمي الرسالة.

DAI يعتمد على DHCP Snooping — بدون جدول Binding ما عنده مرجع يتحقق منه (للأجهزة الثابتة يُستخدم ARP ACL).

07 مثال من شركة

السيرفر الشرعي على المنفذ اللي يربط الـ Switch بالـ Core (Trusted). كل منافذ المكاتب Untrusted. موظف حط راوتر منزلي فيه DHCP شغّال بالغلط ← الـ Snooping يرمي عروضه فورًا، والموظفون يظلّون ياخذون من السيرفر الصحيح. وبوجود DAI، لو أحد حاول ARP Poisoning على البوابة ← يُرفض.

08 أوامر Cisco

DHCP Snooping
SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10
SW1(config)# interface gig0/1        # المنفذ نحو السيرفر/Uplink
SW1(config-if)# ip dhcp snooping trust
SW1(config-if)# exit
SW1(config)# interface fa0/2          # منفذ مستخدم (اختياري: rate limit)
SW1(config-if)# ip dhcp snooping limit rate 10
Dynamic ARP Inspection
SW1(config)# ip arp inspection vlan 10
SW1(config)# interface gig0/1
SW1(config-if)# ip arp inspection trust
# فحص إضافي اختياري:
SW1(config)# ip arp inspection validate src-mac dst-mac ip
Verification
SW1# show ip dhcp snooping
SW1# show ip dhcp snooping binding
SW1# show ip arp inspection
نقاط للتأكد على جهازك: (1) DAI افتراضيًا فيه حدّ لمعدّل حزم ARP على المنافذ Untrusted (شائع أنه ~15 حزمة/ثانية) وتجاوزه ينقل المنفذ لـ err-disabled — أكّد الرقم حسب الـ IOS. (2) أحيانًا Option 82 (ip dhcp snooping information option) تحتاج تعطيلها إذا الـ Switch مو Relay، وإلا يفشل الـ DHCP. هذا يعتمد على الإعداد.

09 أهم ملاحظات CCNA

  • بعد تفعيل Snooping، كل المنافذ Untrusted افتراضيًا — تحط trust يدويًا على الـ Uplink/السيرفر.
  • Snooping يرمي رسائل السيرفر (Offer/Ack) القادمة من منفذ Untrusted، ويسمح برسائل العميل.
  • الـ Binding Table = MAC + IP + Lease + VLAN + Interface، وهو مرجع DAI و IP Source Guard.
  • DAI يعتمد على Snooping؛ للأجهزة الثابتة (بدون DHCP) تستخدم arp access-list.
  • DAI يوقف ARP Spoofing/Poisoning (هجمات MITM على البوابة).

11 أسئلة متوقّعة بالاختبار

بعد تفعيل DHCP Snooping، وش حالة المنافذ افتراضيًا؟

كلها Untrusted. لازم تحدّد ip dhcp snooping trust على منفذ السيرفر/الـ Uplink.

ليش DAI يحتاج DHCP Snooping؟

لأنه يتحقق من مطابقة IP↔MAC مقابل جدول الـ Binding اللي يبنيه الـ Snooping. بدونه ما عنده مرجع (إلا عبر ARP ACL للأجهزة الثابتة).

أي هجوم يوقفه Rogue DHCP prevention؟

سيرفر DHCP مزيّف يوزّع بوابة خاطئة لعمل MITM.

وش يصير لو تجاوز منفذ حدّ معدّل ARP في DAI؟

ينتقل المنفذ عادةً إلى err-disabled (تأكد من قيمة المعدّل حسب الـ IOS).
